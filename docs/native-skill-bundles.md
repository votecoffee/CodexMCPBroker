# Archived: aggregate native skills into Universal Tools

**Retired in 0.19.0.** This document preserves the former experiment only. Its composer, plugin, marketplace and installer commands are no longer shipped; do not follow the installation steps below. Applications keep their own native plugins/skills and use the [shared framework](app-framework.md) and [Skills over MCP](extension-development.md) APIs.

Version 0.12 adds an explicit local skill bundle synchronizer. It composes app-provided native `SKILL.md` folders and their resources into **one Universal Tools plugin**. Apps continue distributing their independent standalone plugins. No app-specific broker code or second installed app plugin is required for this package layout.

This is local installation tooling, separate from the model-facing fourteen-tool MCP surface and runtime [workflow guides](workflow-contributions.md). It does not migrate apps, change service registrations, enable writes, execute contributed scripts or restart Codex. Native skill activation and complete app workflow parity still need fresh-chat acceptance with the app plugins absent.

## Compose, install, reload

After setting up the current broker runtime, use the administrative CLI with its configured state. For example, from the repository root:

```powershell
$Runtime = Get-Content .\plugins\universal-tools\runtime.json -Raw | ConvertFrom-Json
$Manifest = 'C:\Apps\Example\broker-skills\skill-bundle.json'
$Inspection = & $Runtime.python -m universal_tools --state $Runtime.state skills inspect $Manifest | ConvertFrom-Json
& $Runtime.python -m universal_tools --state $Runtime.state skills add $Manifest --expected-sha256 $Inspection.manifest_sha256
& $Runtime.python -m universal_tools --state $Runtime.state skills sync --base-plugin .\plugins\universal-tools
.\scripts\Install-Plugin.ps1
```

`inspect` validates and reports the bundle without selecting it. `add` explicitly trusts the supplied package and snapshots its exact files; review its content and source before adding it. The optional expected manifest digest pins that inspection, and the manifest binds every file by size and SHA-256. Hashes detect content changes; they do not authenticate a publisher or certify the instructions/scripts.

For a selected, trusted bundle, the convenience wrapper performs inspect/add/sync, optionally followed by installation:

```powershell
.\scripts\Sync-Skills.ps1 -BundleManifest $Manifest -Install
```

Restart Codex after installing, then test the native skills in a fresh chat. A package sync alone does not update an already installed cache or existing chat. OpenAI documents [bundled skills, local marketplace updates and restart](https://developers.openai.com/plugins/build/plugins); the local host's copy must be refreshed/installed before reload. MCP server refresh does not perform this packaging operation. [MCP skill import](https://developers.openai.com/plugins/build/skills#import-a-skill-from-mcp) is also a package snapshot, not runtime fetching.

Finish or reconcile active app workflows before refreshing the installed package: the host can replace cached resource paths that an older chat still references. Atomic selection of a generated marketplace release does not make the host's cache update transactional with app state. The synchronizer does not stop the broker, close native targets or reconcile prepared/uncertain operations.

The wrapper uses the runtime pointer generated by setup. It never chooses app directories by scanning the machine. An app installer can invoke the same CLI after the user selects broker integration and its route/skill acceptance is complete; native packages are not installed from arbitrary catalog text.

## App bundle contract, version 1

The former `examples/skill-bundle.schema.json`, synthetic bundle and `skills schema` command were removed with the composer. These historical package files were distinct from service registrations and normalized capability catalogs.

| Field | Requirement |
| --- | --- |
| `schema_version` | Integer `1`. |
| `id`, `version` | Stable lowercase bundle ID and numeric `major.minor.patch` package version. |
| `route` | `universal-tools`; publish a broker variant of direct-tool instructions. |
| `min_broker_version` | Minimum numeric broker version; newer requirements are rejected. |
| `license` | License identifier or expression; include the actual license/notice text in `LICENSE`. |
| `service_ids` | Required broker registrations. Composition checks descriptors locally without connecting to their apps. This does not establish live availability or workflow acceptance. |
| `skills` | Unique native skill names, each beginning with `<bundle-id>-` and matching its folder and frontmatter name. |
| `files` | Exact relative path, byte count, SHA-256 and optional executable flag for every distributed file. |

The directory contains `skill-bundle.json`, `LICENSE` and only inventoried files under `skills/<declared-name>/`. Include referenced instructions, scripts, templates, images and other resources inside those skill folders. `SKILL.md` requires UTF-8 YAML frontmatter, a matching name, a nonempty description and instructions. `agents/openai.yaml` is optional; its original bytes and invocation policy are preserved. Any MCP dependency must name the bundled `universal-tools` server without supplying an additional endpoint or transport. Arbitrary external dependencies are not provisioned.

Use explicit broker calls and current service/tool discovery, contexts, revisions, review, request IDs and outcome reconciliation in the broker variant. Direct `mcp__other_server__...` references and direct MCP dependencies are rejected rather than rewritten. These checks are structural; they cannot prove that every instruction, script or dependency is correctly adapted. Keep common domain guidance in shared source when generating standalone and broker variants.

Paths use portable ASCII letters/digits, dots, underscores, hyphens and internal spaces, with no leading dot/space, traversal, drive/stream syntax, reserved Windows names or trailing dots/spaces. Each component is at most 100 characters and the relative path at most 240. Symbolic links, junctions/reparse points, case aliases, unlisted files and unknown manifest fields are rejected. Package inputs are local directories; ZIP/network fetching and installer/lifecycle hooks are outside this profile.

Limits: 32 skills, 32 service IDs and 256 inventoried files per bundle; 4 MiB per file, 32 MiB per bundle, 64 selected bundles and 64 MiB per composed plugin. Each `SKILL.md` and agent metadata file has a 64 KiB limit. The complete selected release has an additional file-count budget. These packaging limits do not change MCP argument/result budgets or host capacity.

## Snapshots, updates and rollback

All generated state lives under `<state>/skill-bundles/`, normally inside ignored `.local/`:

```text
selection.json                           Explicit desired bundle selection
sources/<manifest-sha256>/               Captured, validated bundle bytes
marketplace/releases/<release-id>/        Complete plugin and release receipt
marketplace/.agents/plugins/marketplace.json
```

Source changes do not alter an accepted snapshot: run `skills add` again to accept a changed package, then sync. Synchronization assembles a new release, verifies it and atomically replaces one marketplace pointer under an OS lock. A failed build leaves the previous pointer intact; abandoned stage directories are never selected. Repeating the same composition is idempotent. Releases are retained; no recursive cleanup or automatic garbage collection runs.

Each release contains one `universal-tools` MCP configuration, the broker's native discovery skill, the selected app skills/resources and app license notices under `assets/bundle-licenses/`. App bundles cannot supply plugin manifests, MCP server definitions or lifecycle hooks. The base source plugin is unchanged. A fresh private runtime pointer binds the generated package to the selected state and CLI interpreter, rather than copying another checkout's pointer. Generated packages therefore contain local configuration and belong outside public source/release ZIPs.

The release ID binds the composition inventory and bundle provenance. The plugin identity remains `universal-tools`; its generated version includes `+skills.<digest-prefix>`. The generated marketplace retains `universal-tools-local` so this is a replacement package, not another app plugin. `Install-Plugin.ps1` verifies the active generated release and refreshes that marketplace source when one exists; it does not silently fall back to the base package on verification failure. Pending bundle selection changes remain pending until sync.

```powershell
& $Runtime.python -m universal_tools --state $Runtime.state skills list
& $Runtime.python -m universal_tools --state $Runtime.state skills status
.\scripts\Sync-Skills.ps1 -RemoveBundle example-app -Install
.\scripts\Sync-Skills.ps1 -RollbackRelease '<full-release-id>' -Install
```

Removal excludes the bundle from the next composed release. Rollback verifies and selects a retained release; it leaves the desired selection unchanged, so status can report `selection_pending`. A later sync uses that desired selection again. Rollback does not revert broker runtime dependencies, app state, registrations or prepared operations; releases requiring another broker runtime version are rejected. Neither operation deletes or disables the app's standalone package.

## Validation boundary

The regression profile covers resource/policy preservation, two-app aggregation, explicit updates/removal, snapshot pinning, collisions, malformed metadata, integrity failures, lock exclusion and interrupted pointer publication. Run `tests/test_skill_bundles.py` and the [source checks](../VERIFICATION.md). Validate native skills with the Skill Creator validator as well.

An isolated Codex profile can additionally exercise actual marketplace install, update and rollback and compare every installed file with the selected release. Keep its `CODEX_HOME`, state, runtime pointers and logs private. This establishes cache packaging behavior for that Codex build; it does not establish skill selection or native app behavior. Finish actual Codex reload/fresh-chat tests for each app's required skills, references, scripts and templates with the app plugin absent. No real app has been migrated merely by adding this synchronizer.
